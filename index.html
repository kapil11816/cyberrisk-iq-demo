Integration requirements before connecting
  • Confirm Tech9 IQ authentication and authorization model (e.g. OAuth/OIDC or service-to-service credentials).
  • Agree organization identifiers, tenant boundaries, field definitions and data ownership.
  • Confirm available APIs, webhook support, rate limits and security review requirements.
  • Use versioned API contracts, audit logs, encryption and explicit consent for data exchange.
  • Never transmit secrets or sensitive assessment data to an unapproved AI provider.

Transparency & governance

Methodology & limitations

A credible product must show how its results are produced and what they do—and do not—mean.

Proposed quantitative method

  1. Define business-relevant cyber loss scenarios.
  2. Estimate event frequency using documented evidence and assumptions.
  3. Estimate primary and secondary financial impacts.
  4. Calculate scenario annualized loss as frequency × average loss magnitude, where suitable.
  5. Model uncertainty and aggregate loss distributions when sufficient data and expertise exist.
  6. Compare selected loss percentiles with policy terms and risk appetite.

Explore FAIR as a methodology reference. A production model needs qualified design and validation.

What this prototype does today

  • Runs in a browser as a standalone demo.
  • Allows company profile and control inputs.
  • Calculates illustrative scenario estimates from deterministic factors.
  • Updates dashboard and report views from entered data.
  • Exports a scenario summary and supports print-to-PDF.

What is not implemented yet

  • Secure user accounts, multi-tenant backend and persistent database.
  • Live integrations with EDR, SIEM, cloud or vulnerability scanners.
  • Statistically validated loss model and calibration dataset.
  • Verified Tech9 IQ API connection.
  • Formal legal, privacy, penetration-test and insurance review.
